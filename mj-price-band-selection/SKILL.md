# 价格带错位选品

v3（2026-11-03）：在 v2 的分析框架上，按黑马选品 skill 的做法改成可执行流程，包括固定规则、默认参数、按轮次的拉数清单、漏斗计数、踩坑记录，以及 Argon 复核。

**目标**：在一个类目里找出“买家已经愿意花钱的价格带里，可以用看得懂、评论能验证的差异，以更合适的价格切进去”的机会，并确认这个价格还能守住利润。

“更便宜”本身不算机会。低价必须同时满足三点，才算错位：需求被满足得更好（至少一样好）；有销量或排名证据；利润算得过来。

---

## 固定规则（改提示词时不要动）
- 利润门槛：**广告前净利率 ≥ 30%，广告后 ≥ 15%**。
- 广告成本固定按售价的 15% 计，不按 CPC 估算；CPC 只用来判断推广阻力，写进备忘。
- 不判断“广告硬推”：第三方数据不准，不因为广告多而剔除。
- 促销排雷只看 BD：增长期内有折扣 > 25% 的 BD 且时间重合，才算“促销拉动”。普通优惠券、小幅降价不算排雷，但常态优惠券和 Prime 价要计入成交价，用来判断商品实际在哪个价格带。
- 材质、结构不能只凭标题或图片定；同款比较必须是同形态、同规格。

## 默认参数（用户没给时用，报告里写明）
| 参数 | 默认值 |
|---|---|
| 站点 | US |
| 售价区间 | < $100 |
| 汇率 | 6.7 |
| 头程 | 海运 $1.4/kg（按体积重和实重取大）；带电专线 $4.5/kg |
| 退货率 | 优先用 Sorftime 类目退货率；没有时取 5%；带电压力测试取 8% |
| 佣金 | 按亚马逊该类目当期佣金表 |
| FBA 配送费、仓储费 | 按亚马逊当期公开费率表，用包装尺寸和重量计算；Q4（10–12 月）用旺季仓储费率 |

## 数据纪律
- 每个数字的来源用以下标签之一：

  | 标签 | 含义 |
  |---|---|
  | 【实测】 | 接口原始返回 |
  | 【计算】 | 由实测数据或公开费率表算出，写公式 |
  | 【推断】 | 由评论、图片或市场结构推出，写依据 |
  | 【假设】 | 只用于利润模型里拿不到的项，写理由并给 ± 区间 |
  | N/A | 没数据，不补数 |

- 每个模块末尾写一行“数据来源：接口名（统计周期）”。
- 价格口径统一：默认用近 90 天成交价中位数，其次当前优惠后价，再次标价，不同口径不混比。另记“促销谷底价”（90 天最低价及持续天数）。
- 规格不同时先折算单位价（每件、每英尺、每平方英尺等，按品类选）再比；多件装、引流小号变体不得当价格带代表。
- 销量口径：卖家精灵 `product_research` 的 units 是**父体口径**，子体销量用 Sorftime 日销近 30 天合计；估算销量写“估算月销”。
- 证据不够就降低结论级别，不硬下结论；候选不够时如实写，不悄悄放宽。

## 流程

拉数统一写成清单交给 batch-offload：先用 `oc_pull.sh`（DeepSeek），额度用完（429）改用 `cb_pull.sh`（CodeBuddy hy3，每批 5 行）。只有 1–2 次的小查询 Claude 自己调。原始返回不读进上下文，只用 Python 打印汇总。

### 第 0 步：确认输入（全流程只停这一次）
1. 卖家精灵 `product_node` 查节点路径和类目名；西柚 `search_market_insight_categories` 搜对应类目（免费）。
2. 一次性向用户确认：
   - 类目是否对；
   - 西柚类目接口（扣 Credits，搜不到就跳过）和外观专利（Sorftime 每次扣 450）查不查；
   - 售价区间、排除品类；
   - 用户已有的成本、供应链、想切的价位（有就用，没有走默认）。
3. 确认后一路跑完，中途不停。

### 第 1 步：全市场样本（第 1 轮清单）
- 卖家精灵 `market_research_statistics`：Top 100 平均月销 M、均价、评论分布。
- Sorftime `category_report`：月销总量、CR3、自营占比、退货率、平均毛利、价格统计。
- 卖家精灵 `market_price_distribution`、`market_brand_concentration`：价格分布和品牌集中度。
- 卖家精灵 `product_research`（售价区间内，**不限评论数**，size 100，按 total_units 降序）：**翻完所有页**。价格带占比要用全市场样本算，不能只用几个竞品。

### 第 2 步：按形态分组，画价格带地图（Python）
1. **按形态分组**（同一父体下挂了不同形态的子体时，单独标出并在组内销量里剔除，否则会虚增该组占比）：从标题提取产品形态（功能 + 结构，例如“磨边机”“玻璃刀”“铅条钳”“入门套装”）。规则先由 Claude 写好，再用 Python 关键词匹配；匹配不上的归“其他”，并抽样检查。多件装、套装单独成组。
2. **每个形态组算**（按父体去重，同父体的子体只计一次销量）：商品数、估算月销合计和占比、价格中位数和四分位（这一步用当前售价；单位价到第 4 步拿到规格后再算）、前 3 名销量集中度、评论门槛（销量前 10 的评论中位数）、前 10 名中评论 < 100 的链接数、星级中位数。
3. **组内再切价格带**：按该组实际价格分布切 2–4 档，不预设区间。每档写：商品数、销量占比、典型配置、头部 ASIN。
4. **输出**：形态组总表 + 价格带地图表 + 漏斗计数（全市场 → 有销量的形态组 → 候选形态组 → 候选价格带）。

| 形态组 | 商品数 | 月销合计/占比 | 价格中位 | 价格区间（P25–P75） | 前 3 集中度 | 评论门槛 | 前 10 低评链接数 | 星级中位 |
|---|---:|---:|---:|---|---:|---:|---:|---:|

### 第 3 步：识别错位，选候选价格带（Python 初筛 + Claude 判断）
**初筛信号**（满足任一项即进入候选，写清触发了哪条）：

| 信号 | 判断方法 | 对应错位类型 |
|---|---|---|
| 主流价带配置雷同 | 销量占比最高的价格带里，前 10 名标题和规格高度相似 | A 改良款进主流价带 |
| 价格空档 | 同形态组按价格排序后，两侧都有销量的价位之间，存在一段几乎没有商品或销量的区间（看分布，不看人为切档） | C 高配进中价带 / B 低成本结构 |
| 低评链接能进头部 | 该价带销量前 10 中，评论 < 100 的链接（按父体去重）≥ 2 个 | 价带防线弱 |
| 高价带有溢价认可 | 高价带星级比中低价带高 ≥ 0.2，且销量占比 ≥ 15%（好评内容到第 4 步再验证） | E 价值表达 / C 高配 |
| 细分人群或场景 | 标题里出现特定人群或场景词（初学者、儿童、旅行、小空间等），且该子组有销量（增长到第 4 步再验证） | D 特定人群 |

**Claude 再判断**：给每个候选价格带写清目标顾客、他们现在买什么、我方差异、目标价格位置、证据强度。没有证据的错位类型写“不适用”，不凑数。

**选标杆**：每个候选价格带挑 2–3 个标杆 ASIN 做深查，包括该价带销量第 1 名、价带里冲得最快的低评新品，以及相邻价带的对照品。候选价格带最多 3 个，标杆合计最多 8 个。

### 第 4 步：标杆深查 + 排雷（第 2 轮清单，每个标杆一组）
| 接口 | 用途 |
|---|---|
| Sorftime `product_trend` DailySalesVolume | 子体日销、近 30 天合计、走势 |
| 卖家精灵 `keepa_info` | 真实上架时间、90 天价格中位数和谷底价、断货重启 |
| 西柚 `get_asin_info_trends`（近 6 个月） | BD、优惠券、价格时间线 |
| 卖家精灵 `asin_detail` | 包装尺寸、重量、品牌、卖家全名、变体 |
| 卖家精灵 `review` starList [1,2,3] | 差评痛点（材质、做工、耐用、规格不符） |
| 卖家精灵 `review` starList [4,5] | 买家认可的价值点（只对高价带标杆查） |
| 卖家精灵 `review` typeList [4] | Vine 评论数（排雷用） |
| Sorftime `ali1688_product_search_from_image`（主图改 `._AC_SL500_.jpg`） | 同款采购价；匹配错写 N/A，改用 `ali1688_product_search` 文字搜索 |

每个候选价格带的核心词，各调一次 `keyword_research`（看搜索量和 CPC）和一次 `keyword_research_trends`（看季节性，也作为第 5 步的大盘对照）。用户同意查外观专利时，对最终推荐的标杆调 Sorftime `patent_search_from_image`。

**排雷**（命中则把该价带的证据强度降一级，并写原因）：
- 促销拉动：销量高点和 BD（折扣 > 25%）重合。
- 老链接翻新：keepa 最早记录早于宣称的上架时间，或同品牌有低星同款老链接。
- Vine 堆分：Vine 占评论 ≥ 50%。
- 季节性：核心词正处于季节高峰。
- 品牌带量：价带里冲上来的新品主要来自同一个成熟店铺（用 `competitor_lookup` 按 sellerName 看店铺规模），新卖家拿不到这份流量。

### 第 5 步：价格与销量的因果（对标杆）
把标价、BD/优惠券、子体日销、评论数放在同一条时间线上（至少 6 个月；上架不足 6 个月的看全部历史，不少于 60 天）。必须做两个对照：
- **大盘对照**：同期该形态核心词的搜索量（`keyword_research_trends`）有没有一起涨。
- **竞品对照**：同期直接竞品有没有涨价、断货或下架。

结论分四级：
- **较强支持**：多个时间点、多项指标方向一致，大盘和竞品两个对照都排除了；
- **有限支持**：方向一致，但观察期短，或有一项替代解释没排除；
- **证据不足**：缺历史价格、销量或促销数据；
- **不支持**：价格变化和销量变化对不上，或有更合理的解释。

### 第 6 步：利润测算（对每个候选价格带）
- **目标售价**：该价带标杆 90 天成交价中位数下浮 15% 和 25% 两档，再加一档“价带下沿价”（该价带 P25）。
- **成本**：采购（1688 人民币价 ÷ 汇率）+ 头程 + 佣金 + FBA 配送费 + 月仓储 + 退货损耗 + 广告（售价 × 15%）。退货损耗 = 退货率 ×（采购 + 头程 + FBA）。
- **带电压力测试**：含插电或电池的产品（烙铁、磨边机等），再按带电专线头程 $4.5/kg、退货率 8% 算一遍，结论以压测结果为准；插电无电池能否走普货，列进验证清单。
- **FBA 尺寸分段**：检查包装多 1 英寸或几盎司会不会跨档；跨档就把两档都算。
- **缺采购价时**：反推“在目标售价下守住利润门槛的最高采购价（人民币）”，交给用户去问工厂。
- **价格锚定**：降价后的售价要和同形态白牌的主流最低价比；仍高于锚定价就视为没有价格优势，按锚定价再算一次。
- **差评集中在“材质薄、易坏、不耐用”时，禁止减料降本**，只能从结构、工艺、供应链整合上降本。

### 第 7 步：写报告 + Argon 复核
- 报告放会话文件夹，文件名 `价格带报告_<类目>.md`，格式见下文。
- 把本提示词和报告一起交给 agy 的 `gemini-4-argon-medium` 挑刺（规则违规、数字矛盾、被忽略的反面证据、推算假设）。Claude 逐条核对，需要补的数据就补查，再改报告，最后说明采纳了哪些、哪里有分歧。

## 结论门槛
- **建议推进**：材质/结构已确认或较可能；第 5 步至少“有限支持”；用真实采购价算的利润达标。
- 任一项缺失（包括只有反推采购价），最高给**小批量验证后推进**。
- 核心事实缺失（真实成交价、子体销量），最高给**继续调研**。
- 价带被成熟店铺带量、或整组月销太小撑不起一个单品，给**不建议进入**并写清原因。

## 输出格式
每个模块末尾写“数据来源：接口名（统计周期）”。

0. **结论摘要**（3 句以内）：有没有价格带错位机会、哪个形态组的哪个价带、属于哪种类型、结论强度、最大风险。
1. **类目基准 + 漏斗计数**：M、全市场样本量、形态组数、候选价带数。
2. **形态组总表 + 价格带地图**。
3. **候选价格带**（每个一节）：
   - 错位逻辑：目标顾客、他们现在买什么、我方差异、目标价位；
   - 标杆对比表：ASIN、形态/规格、90 天中位价/谷底价、单位价、子体月销、评论/星级、上架天数、排雷结果；
   - 价格与销量时间线、两个对照的结果；
   - 评论证据：差评前 3 痛点及占比、好评价值点，并注明抽样范围；
   - 利润表：三档售价 × 广告前/后净利率，每个成本项注明来源标签；
   - 进入建议 + 必须达到的最低差异化 + 主要风险。
4. **被排除的形态组/价带**：一张简表，写原因和触发数据。
5. **下一步验证清单**（3–8 项）：查什么、找谁、怎样算通过。
6. **未执行或偏离的地方**。

## 踩过的坑（来自黑马选品试跑）
- `product_research` 的 units 是父体口径，上架天数也可能不准（实测写 84 天，实际约 50 天）。上架时间用 `asin_detail`、keepa 最早排名记录、Sorftime 日销起始日交叉判断。
- `product_research` 要翻完所有页，只看第 1 页会漏掉新品和长尾。
- hy3 遇到超过约 50KB 的返回会另存成文件：用 `grep -o '/Users/cathug/.codebuddy[^ ]*\.txt'` 取出路径再读。
- Sorftime `product_trend` 的数据是扁平列表 `[日期, 值, 日期, 值…]`，值为 -1 表示没数据。
- 西柚 `get_asin_order_trends` 只有月度数据；日销用 Sorftime，价格和促销用 `get_asin_info_trends`。
- 店铺反查的 `sellerName` 从 `asin_detail` 取完整名，不要用截短的名字。
- 1688 以图搜图对型材、耗材、套装经常匹配错，先看标题再决定用不用。
- `keepa_info` 的 startTimestamp 只往前推 200 天时，“最早记录”就是窗口起点，不能当上架时间；要判断上架时间，至少往前拉 3 年，或直接用 Sorftime 日销起始日。
- 卖家精灵 `keyword_research` 对很长尾的工具词（如 “copper foil hand foiler”）可能没有数据，改用西柚反查标杆的出单词。
